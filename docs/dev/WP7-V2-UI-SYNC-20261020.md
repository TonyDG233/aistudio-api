# WP7 二期：实例化 UI 同步

- 日期：2026-10-20
- 状态：设计稿，待实施
- 依据：`WP5-V4-DESIGN-20261020.md`
- 范围：P1 控制面板、P2 账号管理、P3 系统配置、P4/P5 文案同步
- 原则：实例是用户侧唯一抽象；Context/Page/Slot/资格/命中不进入 UI

---

## 0. 背景

WP7 一期把 WP5 v3 的内部概念直接画进了 UI：

- P1 的“实例数 当前/计划”混用了活页面数与 Slot row 数；
- P2 显示 `@槽N`、资格/挂载/命中、绑定到槽位；
- P3 暴露槽位表、页面上限、预热开关。

WP5 v4 已收敛：

```text
实例 = 一个同时登录的账号会话
max_contexts = 实例上限
```

WP7 二期按此重做 UI。

---

## 1. 术语

| UI | 含义 |
|---|---|
| 账号 | Google 登录身份 |
| 实例 | 一个同时登录的账号会话，有编号 |
| 服务渠道 | 该实例当前可服务 PG / Build |
| 最新 | 当前共享 Chat 选中的实例；只是展示标签，不是路由权重 |
| 在途请求 | 已发到实例、未结束的请求 |
| 实例上限 | `max_contexts`，最多同时登录几个账号 |

不出现：

- 槽位
- Slot row
- 页面 / 页面数 / 页面上限
- 资格 / 命中
- 预热
- 计划实例
- 当前/计划

内部 Context/Page 只在诊断详情出现，且不参与主界面计数。

### 2.2 规则

- 实例数 = active 实例数 / `max_contexts`，写在“实例”标题；
- 可用账号横向条显示 `可用 / 总数` 和 tier 构成：
  - free / pro / ultra / plus；
  - 只显示数量 > 0 的档位；
- 不显示页面数、渠道比值、计划实例；
- 实例行显示：
  - 编号
  - 账号
  - tier
  - 服务渠道
  - 在途请求
  - `最新` 标记（当前共享 Chat 选择）
  - `[切换]` 入口（打开实例切换面板）
- `最新` 只表示当前选择，不改变策略组权重，也不表示自动路由优先级。
- 实例详情只读：
  - 实例状态
  - 账号
  - 服务渠道
  - 在途
  - 内部资源诊断（Context/Page 数量，仅诊断）
- 不显示槽位、Slot row、资格、命中。

### 2.3 状态

- 加载：实例卡 skeleton
- 空：`暂无实例` + `前往账号管理`
- 错误：实例卡错误条 + 重试
- 冷启动：`启动中`
- 回收中：`回收中`，不显示为“已停止”

## 3. P2 账号管理

### 3.1 账号列表

账号平铺，不再使用 Cookie 组 → 子账号层级。来源文件只作为小字。

**组概念保留在后端**：组仍承担账号约束、渠道、额度池和权重，避免与上游 fork 结构冲突；P2 不展示组层级，P3 的“自定义策略组”负责配置。

账号列表的排版可以继续调整，但必须满足：

- 账号行有实例栏；
- 实例栏有 `[切换] [关闭]`；
- `[切换]` 打开实例切换面板；
- 账号列表本身不放 `[+ 新建实例]`。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 账号管理                                      [导入账号] [刷新]             │
│ 一条账号一行；实例有编号；实例是并发登录容量。                               │
├──────────────────────────────────────────────────────────────────────────────┤
│ 已配置账号                          2 个账号 · 2 个实例 · 实例上限 2          │
│                                                                              │
│ u/0  tonygemini38@gmail.com   [pro]                  来源：auth-5.json      │
│ ┌ 实例 #1  Build   使用中   [最新]  [切换] [关闭] ────────────────────────┐ │
│ │ 在途请求：1                                                             │ │
│ └──────────────────────────────────────────────────────────────────────────┘ │
│                                                                              │
│ u/0  odindicola5@gmail.com   [free]                  来源：auth-1.json      │
│ ┌ 实例 #2  PG      使用中          [切换] [关闭] ─────────────────────────┐ │
│ │ 在途请求：0                                                             │ │
│ └──────────────────────────────────────────────────────────────────────────┘ │
│                                                                              │
│ 未登录账号（可选）：[激活实例]                                               │
└──────────────────────────────────────────────────────────────────────────────┘
```

账号列表头部：

- 标题 `已配置账号` 在左；
- `2 个账号 · 2 个实例 · 实例上限 2` 全部集中在右侧；
- 用普通文字，数字加粗；
- 不用胶囊/气泡包装静态信息；
- 搜索和筛选在下一行。

### 3.2 实例切换面板

点击任意实例栏的 `[切换]` 后进入独立面板（不是账号列表本身）：

```text
实例 2 / 2

实例 #1  账号 A  Build  使用中          [切换]
实例 #2  账号 B  PG     使用中          [切换]

[+ 新建实例]
```

规则：

- 面板里**不提供逐实例关闭按钮**；关闭只在账号列表外面的实例栏上；
- 选择运行中的实例 → 切换共享 Chat 的当前账号状态；
- 目标必须 active；启动中/回收中/失效实例不可切换；
- 切换不合并 cookie，不关闭其他实例，不打断在途请求；
- 切换不改变策略组权重；
- `[+ 新建实例]` 在面板底部，点击后选择账号并创建；
- 面板里需要显示容量 `实例 N / M`。

### 3.3 操作

- `切换`：
  - 入口在账号列表实例栏，打开切换面板；
  - 面板内选择目标实例后，执行真实账号状态切换；
  - 不是只改 UI 标签；
  - 其他实例保持原状。
- `关闭`：
  - 只在账号列表实例栏；
  - 有在途返回 409，提示 `该实例仍有在途请求`；
  - 无在途则进入回收，容量释放；
  - 不从切换面板逐行关闭。
- `新建实例`：
  - 只在切换面板；
  - 为该账号占用一个实例容量；
  - 超过上限 409，提示 `实例上限已满，请先关闭一个实例`；
  - 同账号已有实例时 409，提示 `该账号已有实例`。
- 无实例账号：
  - 显示未登录/未激活；
  - 可提供 `激活实例` 入口（账号列表布局是开放项，不固定具体位置）。
- `重新登录`：
  - 账号失效时使用；
  - 不新建重复实例。

### 3.4 状态

- 有实例：显示实例栏；
- 无实例：`未登录` / `未激活`；
- 账号失效：`账号失效`，不允许新建/切换；
- 达到实例上限：新建入口 disabled + `实例上限已满`；
- 冷启动：`启动中`，切换/关闭 disabled；
- 回收中：`回收中`，实例消失前只读；
- 没有“已停止实例”这种长期业务状态。

### 3.5 移除

- Cookie 组 → 子账号层级
- 渠道矩阵
- 槽位徽章
- 资格/挂载/命中
- 绑定到槽位
- 渠道开关
- 页面状态

服务渠道为只读；渠道配置在 P3 高级区。

### 3.6 响应式

- 1024：实例栏单列，操作换行；
- 390：账号信息、实例栏、按钮全部纵向；按钮全宽或两列；
- 切换面板在 390 下单列，实例行按钮全宽，不出现横向滚动；
- 不使用横向滚动的账号表。

## 4. P3 系统与模型配置

### 4.1 基础区

保留：

- 运行状态
- 运行与调度
- 基础功能开关
- 日志与调试
- 接入密钥
- 模型规则与安全（下移）

### 4.2 实例上限

放在深度区最前面，默认 `1`。

```text
┌ 实例上限 ───────────────────────────────────────────────────┐
│ 最多同时登录实例 [1]                                       │
│ 说明：等于反代可同时路由到的账号数；受内存约束。            │
└────────────────────────────────────────────────────────────┘
```

- 不做“单实例/多实例”二元开关；`实例上限 = 1` 就是默认单实例。
- `实例上限 = 1` 时：
  - “自定义策略组”标题和内容完全收起；
  - “高级内存优化”标题和内容完全收起；
  - 显示一行说明：`单实例模式：自定义策略组与内存优化已收起。`
- `实例上限 > 1` 时：
  - 显示两个折叠卡片，默认收起，只留标题和说明；
  - 用户点开后再显示内容。

### 4.3 深度区顺序

1. 实例上限
2. 渠道注册表
3. 路由安全
4. 自定义策略组（可折叠）
5. 高级内存优化（可折叠）
6. 高级协议与回落

### 4.4 自定义策略组

标题改成 `自定义策略组`。

说明写在标题下：

> 默认按 tier 规则路由；组用于收窄账号、渠道、额度池，并调整权重。未配置时不需要关心。

- 标题右侧折叠开关；关闭时只留标题和说明；
- 组内字段保持：
  - 组名 / 启用 / 权重 / 匹配档位 / 邮箱正则 / 允许渠道 / 额度池；
- 单实例上限时整个卡片不渲染。

### 4.5 路由安全

移到“渠道注册表”正下方。

```text
┌ 路由安全 ───────────────────────────────────────────────────┐
│ 单请求换号上限 [2]   熔断窗口/阈值/冷却                     │
│ 排序：可用 → 亲和度 → 权重 → 最久未用 → 请求数 → 编号       │
└────────────────────────────────────────────────────────────┘
```

不出现“当前实例/优先实例”排序项。

### 4.6 高级内存优化

标题右侧折叠开关，默认关闭；单实例上限时不渲染。

说明写在标题下：

> 默认不预加载；开启后增加内存占用，换取更快的渠道切换。

内容（建议，不优先完成）：

```text
┌ 高级内存优化 ───────────────────────────────────────────────┐
│ [ ] 预加载同账号第二渠道页面                               │
│ [ ] 快速切换缓存                                           │
│                                                             │
│ 当前资源（开启并保存后实时更新）                           │
│ CPU  12%    内存  950MB / 16GB    实例 2                    │
│                                                             │
│ [更多选项]                                                  │
└────────────────────────────────────────────────────────────┘
```

- 开关关闭：不采样、不预加载；
- 开关打开并保存：开始上报 CPU/内存，定时刷新；
- “更多选项”后续提供页面上限、缓存保留时间等极客项；
- 默认不暴露页面上限。

### 4.7 移除

- 槽位表
- `slots`
- 计划实例
- 页面上限 / 全局页面上限
- 预热开关（改为高级内存优化，默认关）
- 任何“实例=页面”的文案

内部页面预算仍存在，由后端默认值管理，不出现在 UI。

## 5. 上游兼容说明

- 组是 fork 上游已有概念，后端继续保留 Group/匹配逻辑；
- P2 只做展示层扁平化，不删除组数据；
- 未来拉取上游时，agent 可以协助读 diff、解冲突、跑测试，但结构性删除会放大冲突；
- 因此本设计不删除后端组，只把它收进 P3 的“自定义策略组”。

## 7. 迁移与验收

### 7.1 迁移

- 旧 P2 的槽位/矩阵/三态 UI 全部删除；
- 旧 `slots` 配置不再读取为 UI 实例；
- 旧截图作废，重新拍摄；

### 7.2 视觉验收

五页三档：

```text
1440×900
1024×768
390×844
```

状态：

- P1：正常 / 空 / 加载 / 错误 / 实例启动中
