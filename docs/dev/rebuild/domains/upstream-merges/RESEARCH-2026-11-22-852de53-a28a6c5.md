## 3. 优先候选 Top 7

### Top 1 — `72460f1` 增量 UTF-8 解码（小改动，直接修 bug）

- **上游实质**：`streaming.py` 用 `codecs.getincrementaldecoder("utf-8")(errors="replace")`，避免多字节字符被 XHR 分块切断。
- **本仓缺口**：`src/aistudio_api/infrastructure/gateway/streaming.py:150` 仍是 `payload.decode("utf-8", errors="replace")`。
- **移植要点**：引入 decoder；`chunk` 分支 `decode(payload, final=False)`；流结束后 `decode(b"", final=True)` 并喂给 parser；抽出 `emit_parsed_chunk` 可顺手做，但要保持现有 `latest_finish_reason`/`has_tool_calls`/工具流空闲 STOP 语义。
- **前置依赖**：无。
- **风险**：低。需回归中文/emoji 跨 chunk 用例。

### Top 2 — `fcdc53e` 的“受限账号识别 + 403 诊断”（verify-account 相关）

- **上游实质**：新增 `AccountVerificationRequiredError`/`AccountRestrictedError`；`servicerestricted`、`myaccount.google.com/restrictions`、`available-regions` 识别；403 诊断带 account/signer/pool/UA；未验证/受限账号自动禁用。
- **本仓缺口**：本仓已有 verify-account 标记与隔离（`domain/errors.py:12-27`、`routing_pipeline.py:939-958`），但全库无 `servicerestricted`/`available-regions`/`AccountRestricted` 识别。
- **移植要点**：只移植“识别 + 诊断日志 + 隔离决策”，**不要照搬自动禁用**；地区限制（`available-regions`）是出口 IP/区域问题，不应永久禁用账号，应记录事件并提示代理/地区，避免误杀。
- **前置依赖**：本仓 `AuthError.verification_required` 已存在；需在 `classify_error` 的 403 分支增加受限识别，并在 `routing_pipeline` 的 403 分支区分“账号级 verify”与“IP/区域级 restricted”。
- **风险**：中。误杀账号；诊断日志不得带 Cookie/Authorization。

### Top 3 — `19fe769` 的签名/finish_reason/非流式 keepalive（拆 3 子项）

- **上游实质**：
  - Gemini part 支持 `thinking_signature` / `text_signature` / `standalone_signature`；流式补 `thought_signature` 事件；
  - `finish_reason` 支持字符串与 22→STOP；
  - 非流式请求 10s 后转 keepalive 流，防反向代理 524；
  - 403 第 3 次强制重建 signer；429 区分日配额/短限流。
- **本仓缺口**：`api/responses.py` 的 `to_gemini_parts` 只给 function call/image 带签名，thinking/text 不带；`finish_reasons.py` 无 22→STOP；非流式无 keepalive；日配额区分无。
- **移植要点**：先做 `finish_reasons.py` 的 22/字符串兼容（最小）；再做 `to_gemini_parts` 的签名参数与 `gemini_service.py` 传参；非流式 keepalive 要复用本仓 `sse_keepalive`/`KeepaliveIterator` 思路，不要引入第二套超时账本；403 强制重建 signer 需与本仓 `routing_pipeline` 的 403 同号重签策略对齐。
- **前置依赖**：本仓 `generation_service.py` 已产出 `StreamEvent.thought_signature`；需确认 `wire_parser` 的 candidate 级签名能拆成 thinking/text/standalone。
- **风险**：中。协议槽位/客户端兼容；不得破坏 PG-01..04 与 2s 工具空闲 STOP。

### Top 4 — `a78e54b` 的 Cookie 导入健壮性（优先） + HTTP/2 PING（评估）

- **上游实质**：
  - `parse_raw_cookies` 支持 BOM、Netscape `#HttpOnly_`、JSON 条目过期过滤、域名优先级；
  - `normalize_benefit_tier` 覆盖 TIER0/1/2、AI Pro/Ultra 等；
  - 手动 `PUT /{account_id}/tier`；
  - HTTP/2 PING keepalive 解决长静默流被代理/NAT 断连；
  - ListModels 推断 tier 作为 GetAiStudioBenefitTier 抖动兜底。
- **本仓缺口**：本仓已有 `_cookie_domain_rank`（`cookie_parser.py:228`）与 storage-state 过期过滤，但 `parse_raw_cookies` 未 lstrip BOM，Netscape 分支不处理 `#HttpOnly_`，JSON 条目 `expires` 未过滤；无手动 tier PUT。
- **移植要点**：先移植纯函数级 Cookie 解析增强（BOM/Netscape/过期），加单测；`normalize_benefit_tier` 的扩展可对照本仓 `BENEFIT_TIER_BY_CODE`/`normalize_benefit_tier` 增量补；HTTP/2 PING 依赖上游 `HTTPStreamTransport`，本仓 browserless 走 signer/Go，先评估是否真的需要，不要盲目 monkeypatch httpcore。
- **前置依赖**：Cookie 解析测试；本仓 `cookie_parser` 的 discard policy（AGENT.md §6.1）不能放宽。
- **风险**：中。导入过滤影响登录态；PING 补丁与 httpcore 版本强耦合。

### Top 5 — `62cb23b` Cookie 代际栅栏（并发正确性）

- **上游实质**：请求捕获 `cookie_id`；`is_cookie_generation_current` 校验；`expected_cookie_id` 传入切号；`StaleSessionError`；旧异步结果不得处罚新导入凭据；signer 输入指纹/worker lease。

- **移植要点**：在 `AccountMeta.cookie_id` 基础上增加代际校验；`routing_pipeline` 的 403/401 异步结果回写前校验代际；`account_service.rotate_account_cookies` 写入前校验；不要照搬上游 Go `workerLease`，本仓 signer 已有 `poolstate` 延迟重建。
- **前置依赖**：先补并发回归测试（导入/切号/403 轮换交叉）。
- **风险**：中高。跨 account/routing/signer；改动面大，建议单独一轮。

### Top 6 — `a28a6c5` 安全与缓存失效（低风险高收益）

- **上游实质**：API key `secrets.compare_digest`；dump URL 脱敏/512KB 截断；config 原子写；tier 变更同步 active context + `model_discovery.invalidate_cache()`；retry 配置化；资源回收。
- **本仓缺口**：`api/dependencies.py:264` 仍是 `token in all_valid_keys`（非恒定时间）；本仓无 `model_discovery.invalidate_cache()`，tier 变更后模型缓存可能 600s 才刷新；本仓 dump URL 已由 `sanitize_log_message` 脱敏，无需重复。
- **移植要点**：只移植 `compare_digest` 与 tier 变更后的模型缓存失效；`account_store`/`transport` 大改不要整块 pick；config 原子写本仓已有 `_atomic_write_text`。
- **前置依赖**：无。
- **风险**：低。注意 `compare_digest` 要对每个有效 key 逐个比较，空 key 跳过。

### Top 7 — `036e618` 代理字符安全 + Termux DNS（环境健壮性）

- **上游实质**：`encode("utf-8", errors="replace")` 防止 lone surrogate 抛异常；Go `EnsureFallbackDNS` 解决 Termux 无 `/etc/resolv.conf`；PS 脚本加固。
- **本仓缺口**：`browserless_session.py:533` 是 `sha256(prompt.encode("utf-8"))`，遇到 JSON 中的孤立代理字符会抛 `UnicodeEncodeError`；本仓 signer 是否有 DNS fallback需核对。
- **移植要点**：所有对外文本 `encode("utf-8")` 改为 `errors="replace"`（digest、IPC、transport body）；DNS fallback 只在 Termux/Android 生效，不要影响 Windows/Linux 正常解析。
- **前置依赖**：无。
- **风险**：低。`replace` 会改变 digest 输入字节，需确认只影响异常字符。
