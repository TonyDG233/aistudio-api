# WP5 / 实例与切换：完整逻辑

- 日期：2026-10-21
- 状态：唯一设计口径
- 范围：后端实例生命周期、容量、路由、切换；前端 P1/P2/P3/P4/P5
- 目标：先讲清概念，再允许实现。实现与本文冲突时，以本文为准。

---

## 1. WP5 在解决什么

WP5 不是“多做几个页面”，而是解决：

1. 反代能同时登录几个账号（浏览器上下文上限）；
2. 每个账号能开出几个渠道用量窗口（实例上限）；
3. 切换实例时，如何不合并 cookie、不浪费内存、不打断请求；
4. 路由如何在多个实例之间选择；
5. 用户界面只表达“实例”，不暴露 Context/Page/Slot。

用户层只有一个核心概念：**实例 = 一个用量窗口 = 一个账号的一个渠道单位**。

---

## 2. 四个层次

```text
账号 ──→ 浏览器上下文（每个账号 1 个，内部资源）
  │
  └──→ 实例（账号 + 渠道 = 用量窗口，用户可见）
          └──→ 渠道页面（每个 active 实例 1 个，内部资源）
```

### 2.1 账号

Google 登录身份，例如：

```text
tonygemini38@gmail.com
```

### 2.2 实例

**一个用量窗口，等于“一个账号 + 一个渠道”的一个单位。**

```text
实例 #1 · 账号 A · PG      · 使用中
实例 #2 · 账号 A · Build   · 使用中
实例 #3 · 账号 B · PG      · 使用中
```

规则：

- 实例按 **账号 + 渠道** 计数，不按账号计数；
- 同一账号的 PG 和 Build 是 **两个实例、两个独立用量窗口**；
- 同一账号的多个实例共享一个浏览器上下文；
- 实例有稳定编号；
- 渠道是实例的固有属性，不是实例内部的二级菜单；
- 没有 active 实例时，只剩 `实例 2 / 2` 这样的容量数字。

### 2.3 浏览器上下文

后端实现：

- 一个账号一个浏览器上下文，隔离 cookie；
- 不同账号不能共用一个上下文；
- 同一账号的多个渠道实例共用一个上下文；
- Context 不进入用户 UI/API。

### 2.4 渠道页面

- 每个 active 实例对应一个渠道页面；
- 同一账号两个实例 = 同一上下文里的两个页面；
- 页面只在实例激活时创建；
- 默认不预加载；
- Page/Slot 不进入用户 UI/API。

资源关系：

```text
账号 A → 上下文 A
           ├─ 实例 #1（A · PG）   → PG 页面
           └─ 实例 #2（A · Build）→ Build 页面

账号 B → 上下文 B
           └─ 实例 #3（B · PG）   → PG 页面
```

合法形态：

- **2c1p**：两个账号各一个渠道实例 → 2 实例、2 上下文、2 页面。
- **1c2p**：一个账号 PG+Build → 2 实例、1 上下文、2 页面。
- **2c3p**：A-PG + A-Build + B-PG = 3 个用量窗口 → 超过实例上限，禁止。

## 3. 启动行为

**项目启动时，`max_contexts` 是多少，就自动启动多少个账号。**

例如：

```yaml
routing:
  max_contexts: 2
```

启动时：

- 自动选择 2 个可用账号；
- 每个账号创建一个浏览器上下文；
- 每个账号按默认渠道创建一个实例（一个用量窗口）；
- 同一账号的默认渠道不重复创建实例；
- 跳过失效账号；
- 可用账号不足时，能启动几个就启动几个；
- 单个账号启动失败只记录日志，不阻塞其他账号；
- 启动完成后，`latest` 是最后一个成功启动的实例；
- `current` 默认指向第一个成功启动的实例，或当前活跃账号对应的实例。

选择账号的顺序：

1. 当前活跃账号优先；
2. 其余按现有旋转顺序；
3. 跳过失效/凭据缺失账号；
4. 同一账号同一渠道不创建重复实例。

启动失败不会伪造账号或占位实例。

运行期间修改 `max_contexts` **不会**自动补启动实例；新值在下次项目启动时生效，除非用户显式新建实例。

关闭实例后也不自动补位；是否重新填满由用户或下次启动决定。

## 4. 容量与内存

```text
max_contexts = 同时登录账号/上下文上限，也是启动预启动数量
max_instances = 同时 active 的用量窗口上限
```

实例上限与账号上限分开计算：

```text
max_instances = max(max_contexts, 2)
```

这样：

- `max_contexts=2` 时最多 2 个实例，启动 2 个账号、各 1 个默认渠道实例；
- `max_contexts=1` 时仍允许该账号的 PG+Build 两个实例（1c2p），但不会出现第二个 context；
- 任何情况下都不为了切换强行开第三个 context 或第三个用量窗口。

内存规则：

- 只有 active 实例占用渠道页面内存；
- 未激活/已关闭实例不占页面；
- 一个账号只有在最后一个实例关闭后才回收 context；
- 同一账号的多个实例共用一个 context，不重复 cookie；
- 默认不预加载；
- 页面预算至少覆盖 `max_instances`；
- 全局/渠道/组页面预算都是后端内存保护，不进入主 UI；
- Build-only 账号为 BotGuard 捕获创建的内部 bootstrap 页应在捕获后关闭或复用，不能把它当作额外实例，也不能长期白占页面内存；
- 关闭实例释放页面；最后一个实例关闭时释放上下文。

如果 `max_contexts=2`，启动时自动启动 2 个账号，这是用户选择的内存占用；运行中不需要为了切换强行再开第三个。

## 5. 状态

用户可见状态只有：

```text
启动中
使用中
回收中
失效
```

状态属于实例，不属于账号。

- 关闭实例后该实例从列表消失；
- 同一账号还有其他实例时，账号与 context 保留；
- 关闭账号最后一个实例后，context 回收；
- 缓存尚未释放时短暂显示“回收中”；
- 失效账号不能新建/切换；
- 没有 active 实例时不存在实例，只剩容量数字。

## 6. 切换实例

点击实例栏的 `[切换]` 进入切换面板。切换的单位是**实例（账号 + 渠道）**，不是账号。

### 6.1 情况 A：目标实例已经 active

```text
直接切换 current 到目标实例
不关闭旧实例
不新建实例
```

这是两个实例本来都已运行的情况，例如 2c1p 的 A-PG 与 B-PG，或 1c2p 的 A-PG 与 A-Build。

### 6.2 情况 B：目标实例不存在，实例上限已满

```text
等待被替换实例的在途请求结束
→ 关闭被替换实例
→ 回收该实例的页面；若它是该账号最后一个实例，再回收 context
→ 启动目标实例（账号已有 context 则复用）
→ 切换 current
```

不静默中断另一个实例的在途请求；不能等待时返回 409。

### 6.3 情况 C：目标实例不存在，实例上限有空

```text
复用目标账号已有 context（没有则创建）
→ 启动目标实例
→ 切换 current
```

是否保留旧实例由实例上限与实际路由需求决定；切换本身不要求双活，也不要求为了切换强行多开。

### 6.4 在途请求

不能直接杀掉。

- 等待在途请求结束再切；
- 或返回 409，提示当前不能关闭；
- 不静默中断另一个实例的请求。

### 6.5 切换边界

- 不合并 cookie；
- 不把两个账号塞进一个登录态；
- 不改变策略组权重；
- 切换成功后才更新 `current`；
- 关闭旧实例和启动新实例是容量操作，不是只改 UI 字段；
- 目标必须在切换完成后 active。

`latest` 是“最近启动的实例”，只用于 `[最新实例 ?]` 展示，不是切换选择，也不参与策略组权重。

## 7. 渠道选择与预算

切换面板必须有渠道按钮；每个按钮创建或切换的是**一个实例（用量窗口）**。

```text
实例 2 / 2

实例 #1  账号 A · PG      使用中      [最新实例 ?]  [切换]
  账号 A 的另一个渠道：[Build · 启动并切换 / 实例上限已满]

实例 #2  账号 B · PG      使用中                   [切换]

[+ 新建实例]
```

按钮规则：

| 情况 | 按钮 |
|---|---|
| 该渠道实例已经 active，且不是当前实例 | `[PG · 切换]` / `[Build · 切换]` |
| 该渠道实例不存在，实例上限与预算允许 | `[PG · 启动并切换]` |
| 该渠道实例不存在，实例上限或预算不足 | `[PG · 预算不足]` / `[实例上限已满]`，灰掉 |
| 目标是当前实例 | `[PG · 使用中]`，不可重复切换 |

- 已 active 实例切换不创建新页面、不消耗新实例容量；
- “启动并切换”会创建一个新实例和一个新页面，必须同时通过实例上限和页面预算；
- 同一账号同一渠道不能重复创建实例；
- 同一账号不同渠道允许创建第二个实例，但总实例数不能超过 `max_instances`，context 不增加；
- 如果切换动作会关闭旧实例并释放页面，先按释放后的可用容量计算；
- 前端可以禁用按钮，后端必须再次校验；
- 渠道按钮直接显示，不用隐藏下拉；
- 不把渠道选项塞进二级弹窗。

设置页提供有效预算值：

- 全局页面预算；
- 单渠道页面预算；
- 组页面预算；
- 预加载开关。

这些值放在高级设置/高级内存优化，不放在主界面。

## 8. 账号列表

账号列表只负责账号和实例栏，不负责新建实例。

```text
已配置账号                 2 个账号 · 2 个实例 · 实例上限 2

tonygemini38@gmail.com  [pro]  可用
  实例 #1  A · PG     使用中  [最新实例 ?]  [切换] [关闭]
  实例 #2  A · Build  使用中                  [切换] [关闭]

odindicola5@gmail.com   [free] 可用
  实例 #3  B · PG     使用中                  [切换] [关闭]
```

规则：

- 标题在左；
- 账号数、实例数、实例上限集中右侧；
- 实例数按用量窗口计数，不按账号计数；
- 同一账号可以有多个实例行，每行一个渠道；
- 用普通文字和加粗数字，不用胶囊/气泡包装静态信息；
- 默认只显示邮箱、tier、状态、实例栏；
- 来源文件、最近使用、Cookie 标识移入详情/tooltip；
- 操作按钮紧凑，不堆满文字；
- 每个实例栏有 `[最新实例 ?] [切换] [关闭]`；
- `[关闭]` 关闭该实例；账号还有其他实例时，context 保留；
- `[关闭]` 只在实例栏，不进入切换面板；
- 账号列表不放 `[+ 新建实例]`；
- 账号未登录时显示未登录/未激活，不显示页面、槽位、资格、命中；
- 不在账号列表展开 context/page 信息。

## 9. 切换面板

- 点击实例栏 `[切换]` 打开；
- 显示 `实例 N / M`，N/M 按用量窗口计数；
- 实例行显示账号、tier、渠道、状态；

- 没有实例的账号只在点 `[+ 新建实例]` 后出现；
- 切换面板的渠道按钮按实例上限和页面预算启用/灰掉；
- 同一账号已有其他渠道实例时，新渠道按钮创建第二个实例，而不是第二个 context。

## 10. 新建实例

`[+ 新建实例]` 属于切换面板，不属于账号列表。

```text
新建实例

选择账号：
  [ 账号 C  free  ▾ ]

选择渠道：
  [PG · 可用]   [Build · 预算不足]  ← 按实例上限/页面预算灰掉

[创建并切换]   [取消]
```

规则：

- 可以选择已有其他渠道实例的账号；
- 同一账号同一渠道已有实例时返回 409；
- 新建一个实例消耗一个用量窗口容量；
- 只有该账号还没有 context 时，才额外消耗一个 context 容量；
- 实例上限已满时禁用并提示“实例上限已满”；
- 初始渠道同样受页面预算限制；
- 创建成功后实例成为最新，并切换到该实例；
- 创建失败不会留下半实例，也不会留下半 context；
- 空闲容量不会被账号提前占位。

---

## 11. 关闭实例

只在账号列表的实例栏操作，关闭的是该实例（账号 + 渠道）。

- 有在途请求：409，提示“该实例仍有在途请求”；
- 无在途：关闭该实例页面，进入回收中，随后从列表消失；
- 若该账号还有其他实例，context 保留，其他实例不受影响；
- 若这是该账号最后一个实例，回收 context；
- 关闭释放实例容量；最后一个实例关闭时同时释放 context 容量；
- 其他实例不关闭、不打断；
- 当前实例关闭后，如果还有 active 实例，回退到最近启动的 active 实例；没有则为空；
- 关闭后不自动补位，是否填满由下次启动或用户新建决定。

## 12. 路由

请求仍按资格图自动路由：

```text
渠道/能力 → 候选实例 → 组约束 → 排序 → 页面落地
```

候选实例 = 所有 active 的“账号 + 渠道”用量窗口。

排序继续使用：

- 健康/冷却；
- 渠道亲和；
- 组权重；
- 最久未使用；
- 请求数/权重；
- 编号兜底。

规则：

- 切换实例不改变策略组权重；
- 切换实例不改变渠道资格；
- 手动切换只改变当前使用的实例（用量窗口）；
- `[最新实例 ?]` 不参与排序；
- 组只做约束，不是独立实例池；
- 同账号多渠道共用一个 context，但每个渠道是独立实例、独立用量窗口；
- 启动时填满 `max_contexts` 是为了账号可用性；实例数由 `max_instances` 另行约束；
- 不为“保留旧实例”额外开实例，除非容量和路由确实需要。

## 14. P3 设置

- 实例/账号上限放在深度设置最前面；
- `max_contexts` 默认 1；
- `max_instances = max(max_contexts, 2)`，保证单账号也能开 PG+Build（1c2p）；
- 上限为 1 时，自定义策略组和高级内存优化整卡收起；
- 上限大于 1 时，两张卡默认折叠；
- 自定义策略组只做约束，不是独立实例池；
- 路由安全放在渠道注册表下方；
- 页面预算/预加载放在高级内存优化：
  - 全局页面预算；
  - 单渠道页面预算；
  - 预加载；
  - 预算至少覆盖 `max_instances`；
- 切换面板读取这些有效预算；
- 前端可禁用按钮，后端必须校验。

## 15. 后端结构

### 15.1 实例领域

```text
Instance
  id
  number
  account_id
  channel: "pg" | "build"
  state: starting | active | reclaiming | invalid
  in_flight
  latest
```

`current` 是当前使用实例的选择，放在 manager 内部状态或列表的 `current_instance_id`；它不是策略组权重。

`context` 不进入实例领域；同一账号的多个实例在 pool 层共用一个上下文。

### 15.2 API

```text
GET    /api/instances
POST   /api/instances                       { account_id, channel }
DELETE /api/instances/{id}
POST   /api/instances/{id}/switch
POST   /api/instances/{id}/reassign         { account_id }
```

`GET /api/instances` 只返回：

```json
{
  "max_instances": 2,
  "latest_instance_id": "inst-1",
  "current_instance_id": "inst-1",
  "instances": [
    {
      "id": "inst-1",
      "number": 1,
      "account_id": "acc_a",
      "channel": "pg",
      "state": "active",
      "in_flight": 0,
      "latest": true
    }
  ]
}
```

不返回 Context/Page/Slot/资格/命中/页面计数。

### 15.3 切换

`POST /api/instances/{id}/switch`

1. 目标实例已 active：只切换 `current`，不关闭旧实例；
2. 目标实例不存在且实例上限有空：启动目标实例；
3. 目标实例不存在且实例上限已满：等待在途结束，关闭被替换实例，再启动目标；
4. 关闭一个实例只释放它自己的页面；关闭账号最后一个实例才释放 context；
5. 启动目标时若账号已有 context 则复用，否则创建；
6. 调用真实账号状态切换；
7. 切换成功后才更新 `current`；
8. 不合并 cookie，不改变策略组权重。

### 15.4 启动预载

```text
读取 max_contexts = N
→ 选择最多 N 个可用账号
→ 每个账号创建一个 context
→ 每个账号按默认渠道创建一个实例
→ 失败的账号记录日志并跳过
→ 启动完成后更新 latest/current
```

- 同一账号同一渠道不重复；
- 不伪造账号；
- 不因为某个账号失败而阻塞其他账号；
- 运行中改上限不自动补启动；
- 关闭后不自动补位。

## 16. 测试与验收

### 后端

- 启动时 `max_contexts=2` 自动启动 2 个可用账号、2 个默认实例；
- 可用账号不足时启动实际数量；
- 同一账号同一渠道不重复启动；
- 两个账号各一个渠道 → 2 实例、2 上下文、2 页面；
- 同一账号 PG+Build → 2 实例、1 上下文、2 页面（1c2p）；
- 同一账号同一渠道重复创建 → 409；
- 同一账号不同渠道创建第二个实例 → 允许，但不超过 `max_instances`；
- 2c3p → 第 3 个实例被拒绝，不留下半页面/半 context；
- 容量满 → 409；
- 有在途关闭 → 409；
- 切换 active 目标不关闭旧实例；
- 容量满且目标未 active → 关闭被替换实例后启动目标；
- 关闭一个实例不影响同账号另一个实例；
- 关闭账号最后一个实例才回收 context；
- 切换调用真实账号状态切换，失败时 current 不变；
- 切换渠道预算不足 → 409，不留下半页面；
- API 不包含 Context/Page/Slot/资格/命中。

### 前端

- 账号列表头部信息集中在右侧，不使用气泡；
- 实例栏有 `[最新实例 ?] [切换] [关闭]`；
- 同一账号多个渠道显示为多个实例行；
- 切换面板没有逐实例关闭；
- 切换面板渠道按钮按实例上限/预算正确启用/灰掉；
- 已 active 渠道显示切换，不显示启动；
- 空闲容量没有账号占位；
- `+ 新建实例` 只在切换面板；
- 新建实例选择账号和渠道；
- 切换后当前实例状态实际改变；
- 1440/1024/390 三档无溢出、无遮挡、无按钮不可点；
- 390 下渠道按钮可换行，不横向滚动。

## 17. 明确不做

- 不把 Context/Page/Slot 作为用户概念；
- 不把同一账号的 PG/Build 合并成一个实例；
- 不按账号数冒充实例数；
- 不在账号列表放 `[+ 新建实例]`；
- 不在切换面板放关闭按钮；
- 不做虚假的“当前实例/最新实例”路由优先级；
- 不合并 cookie；
- 不为没有账号的空闲容量造占位账号；
- 不在切换时强行要求两个实例 active；
- 不为了切换强行开第三个 context 或第三个用量窗口；
- 验收通过前不 push。
