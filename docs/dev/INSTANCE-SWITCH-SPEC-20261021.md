# WP5 / 实例与切换：完整逻辑

- 日期：2026-10-21
- 状态：唯一设计口径
- 范围：后端实例生命周期、容量、路由、切换；前端 P1/P2/P3/P4/P5
- 目标：先讲清概念，再允许实现。实现与本文冲突时，以本文为准。

---

## 1. WP5 在解决什么

WP5 不是“多做几个页面”，而是解决：

1. 反代能同时登录几个账号；
2. 每个账号能使用哪些渠道；
3. 切换账号时，如何不合并 cookie、不浪费内存、不打断请求；
4. 路由如何在多个账号之间选择；
5. 用户界面只表达“实例”，不暴露内部资源概念。

用户层只有一个核心概念：**实例**。

---

## 2. 四个层次

```text
账号 → 实例 → 浏览器上下文 → 渠道页面
```

### 2.1 账号

Google 登录身份，例如：

```text
tonygemini38@gmail.com
```

### 2.2 实例

**一个同时登录的账号会话，近似 Context。**

```text
实例 #1 · 账号 A · PG + Build · 使用中
实例 #2 · 账号 B · PG        · 使用中
```

规则：

- 一个账号对应一个实例；
- 实例有稳定编号；
- `max_contexts` 是同时登录实例上限，也是反代能同时路由到的账号数；
- 同一账号同时服务 PG/Build，仍然是**一个实例**；
- 渠道是实例内部能力，不是第二个实例；
- 没有账号占用时，不存在实例，只剩 `实例 2 / 2` 这样的容量数字。

### 2.3 浏览器上下文

后端实现：

- 一个账号一个浏览器上下文，隔离 cookie；
- 不同账号不能共用一个上下文；
- 同一账号的多个渠道可以共用一个上下文。

### 2.4 渠道页面

- PG 页面、Build 页面是实际页面；
- 同一账号两个渠道可以共用上下文、各有一个页面；
- 页面只在渠道激活时创建；
- 默认不预加载；
- Context、Page、Slot 都不进入用户 UI/API。

资源关系：

```text
账号 A → 实例 #1 → 上下文 A
                     ├─ PG 页面
                     └─ Build 页面

账号 B → 实例 #2 → 上下文 B
                     └─ PG 页面
```

正常两账号：两个实例、两个上下文、各一个页面。
同账号两渠道：一个实例、一个上下文、两个页面。

---

## 3. 启动行为

**项目启动时，`max_contexts` 是多少，就自动启动多少个账号实例。**

例如：

```yaml
routing:
  max_contexts: 2
```

启动时：

- 自动选择 2 个可用账号；
- 每个账号创建一个实例；
- 每个实例按账号默认渠道初始化；
- 不重复启动同一账号；
- 跳过失效账号；
- 可用账号不足时，能启动几个就启动几个；
- 单个账号启动失败只记录日志，不阻塞其他账号；
- 启动完成后，`latest` 是最后一个成功启动的实例；
- `current` 默认指向第一个成功启动的实例，或现有活跃账号对应的实例。

选择账号的顺序：

1. 当前活跃账号优先；
2. 其余按现有旋转顺序；
3. 跳过失效/凭据缺失账号；
4. 不创建重复实例。

启动失败不会伪造账号或占位实例。

运行期间修改 `max_contexts` **不会**自动补启动实例；新值在下次项目启动时生效，除非用户显式新建实例。

关闭实例后也不自动补位；是否重新填满由用户或下次启动决定。

---

## 4. 容量与内存

```text
max_contexts = 同时登录实例上限
```

它有两个作用：

1. 硬上限；
2. 项目启动时的预启动数量。

内存优化规则：

- 只有 active 实例占用浏览器上下文和页面内存；
- 未激活的实例只是逻辑目标，不占运行内存；
- 默认不预加载；
- 高级内存优化可开启预加载，但默认关闭；
- 页面预算至少能容纳每个 active 实例一个页面；
- 全局/渠道/组页面预算都是后端内存保护，不进入主 UI；
- 预算值放在高级设置，供切换面板判断按钮是否可用；
- 关闭实例释放上下文和页面，容量释放。

如果 `max_contexts=2`，启动时自动启动 2 个账号，这是用户选择的内存占用；运行中不需要为了切换强行再开第三个。

## 5. 状态

用户可见状态只有：

```text
启动中
使用中
回收中
失效
```

没有“已停止实例”这种长期业务状态。

- 关闭后实例从列表消失；
- 缓存尚未释放时短暂显示“回收中”；
- 失效账号不能新建/切换；
- 没有账号占用时不存在实例，只剩容量数字。

## 6. 切换实例

点击实例栏的 `[切换]` 进入切换面板。

### 6.1 情况 A：目标实例已经 active

```text
直接切换当前使用的账号状态
不关闭旧实例
不新建实例
```

这是两个实例本来都已运行时的情况。

### 6.2 情况 B：目标没有 active 实例，容量已满

```text
等待当前实例在途请求结束
→ 关闭当前实例
→ 回收资源、释放容量
→ 启动目标实例
→ 切换过去
```

`max_contexts=1` 时，切换就是：

```text
先关旧，再开新
```

不是：

```text
旧实例保持 active + 再开一个新实例
```

### 6.3 情况 C：目标没有 active 实例，容量有空

可以启动目标再切换。

是否保留旧实例由容量与实际路由需求决定；切换本身不要求双活，也不要求为了切换强行多开。

### 6.4 在途请求

不能直接杀掉。

- 等待在途请求结束再切；
- 或返回 409，提示当前不能关闭；
- 不静默中断另一个实例的请求。

### 6.5 切换边界

- 不合并 cookie；
- 不把两个账号塞进一个登录态；
- 不改变策略组权重；
- 切换成功后才更新 `current`；
- 关闭旧实例和启动新实例是容量操作，不是只改 UI 字段；
- 目标必须在切换完成后 active。

`latest` 是“最近启动的实例”，只用于 P1/账号栏的 `[最新实例 ?]` 展示，不是切换选择，也不参与策略组权重。

## 7. 渠道选择与预算

切换面板必须有渠道按钮。

```text
实例 2 / 2

实例 #1  账号 A  Build  使用中      [最新实例 ?]
  [PG · 启动并切换]   [Build · 切换]

实例 #2  账号 B  PG     使用中
  [PG · 切换]         [Build · 启动并切换 / 预算不足]

[+ 新建实例]
```

按钮规则：

| 情况 | 按钮 |
|---|---|
| 渠道已经 active | `[PG · 切换]` / `[Build · 切换]` |
| 渠道未 active，预算允许 | `[PG · 启动并切换]` |
| 渠道未 active，预算不足 | `[PG · 预算不足]`，灰掉 |
| 目标是当前实例的当前渠道 | `[PG · 使用中]`，不可重复切换 |

- 已 active 渠道切换不消耗新页面预算；
- 只有“启动并切换”会新增页面、消耗预算；
- 如果切换动作会关闭旧实例并释放页面，先按释放后的可用预算计算；
- 前端可以禁用按钮，后端必须再次校验；
- 渠道按钮直接显示，不用隐藏下拉；
- 不把渠道选项塞进二级弹窗。

设置页提供有效预算值：

- 全局页面预算；
- 单渠道页面预算；
- 组页面预算；
- 预加载开关。

这些值放在高级设置/高级内存优化，不放在主界面。

## 8. 账号列表

账号列表只负责账号和实例栏，不负责新建实例。

```text
已配置账号                 2 个账号 · 2 个实例 · 实例上限 2

tonygemini38@gmail.com  [pro]  可用
  实例 #1  Build  使用中  [最新实例 ?]  [切换] [关闭]

odindicola5@gmail.com   [free] 可用
  实例 #2  PG     使用中                  [切换] [关闭]
```

规则：

- 标题在左；
- 账号数、实例数、实例上限集中右侧；
- 用普通文字和加粗数字，不用胶囊/气泡包装静态信息；
- 默认只显示邮箱、tier、状态、实例栏；
- 来源文件、最近使用、Cookie 标识移入详情/tooltip；
- 操作按钮紧凑，不堆满文字；
- 每个实例栏有 `[最新实例 ?] [切换] [关闭]`；
- `[关闭]` 只在实例栏，不进入切换面板；
- 账号列表不放 `[+ 新建实例]`；
- 账号未登录时显示未登录/未激活，不显示页面、槽位、资格、命中；
- 不在账号列表展开渠道矩阵。

## 9. 切换面板

- 点击实例栏 `[切换]` 打开；
- 显示 `实例 N / M`；
- 实例行显示账号、tier、状态、渠道按钮；
- 面板内**没有逐实例关闭按钮**；
- `[+ 新建实例]` 在面板底部；
- 空闲容量就是空着的容量，不显示“未激活账号”占位行；
- 没有实例的账号只在点 `[+ 新建实例]` 后出现；
- 切换面板的渠道按钮按预算启用/灰掉。

---

## 10. 新建实例

`[+ 新建实例]` 属于切换面板，不属于账号列表。

```text
新建实例

选择账号：
  [ 账号 C  free  ▾ ]

选择初始渠道：
  [PG · 可用]   [Build · 预算不足]  ← 按预算灰掉

[创建并切换]   [取消]
```

规则：

- 只能选择没有实例、未失效的账号；
- 新建消耗一个并发账号容量；
- 容量已满时禁用并提示“实例上限已满”；
- 同账号已有实例返回 409；
- 初始渠道同样受预算限制；
- 创建成功后实例成为最新，并切换到该实例；
- 创建失败不会留下半实例；
- 空闲容量不会被账号提前占位。

---

## 11. 关闭实例

只在账号列表的实例栏操作。

- 有在途请求：409，提示“该实例仍有在途请求”；
- 无在途：进入回收中，随后从列表消失；
- 关闭释放容量；
- 其他实例不关闭、不打断；
- 当前实例关闭后，如果还有 active 实例，回退到最近启动的 active 实例；没有则为空；
- 关闭后不自动补位，是否填满由下次启动或用户新建决定。

---

## 12. 路由

请求仍按资格图自动路由：

```text
渠道/能力 → 候选实例 → 组约束 → 排序 → 页面落地
```

排序继续使用：

- 健康/冷却；
- 渠道亲和；
- 组权重；
- 最久未使用；
- 请求数/权重；
- 编号兜底。

规则：

- 候选 = 所有 active 实例；
- 切换实例不改变策略组权重；
- 切换实例不改变渠道资格；
- 手动切换只改变当前使用的账号状态；
- `[最新实例 ?]` 不参与排序；
- 组只做约束，不是独立实例池；
- 同账号多渠道由后端共用一个上下文，不产生第二实例。

启动时填满 `max_contexts` 是为了可用性；切换时不要为了“保留旧实例”而额外开实例，除非容量和路由确实需要。

## 13. P1 控制面板

```text
当前实例（左，跨两行）        可用账号
                              总请求数
```

- 左侧实例列表可随实例数量向下延伸；
- 右侧两个卡片高度与左侧跨行同步；
- 实例行显示编号、账号、tier、渠道、在途、`[最新实例 ?]`；
- 实例行有 `[切换]`，打开切换面板；
- 不出现重复实例数卡、Context 卡、页面数卡；
- `429 尝试` 改为 `429 限额`；
- 可用账号信息放大，不做扁平成一条的比值。

## 14. P3 设置

- 实例上限放在深度设置最前面；
- 默认 1；
- 上限为 1 时，自定义策略组和高级内存优化整卡收起；
- 上限大于 1 时，两张卡默认折叠；
- 自定义策略组只做约束，不是独立实例池；
- 路由安全放在渠道注册表下方；
- 页面预算/预加载放在高级内存优化：
  - 全局页面预算；
  - 单渠道页面预算；
  - 预加载；
  - 预算至少覆盖 `max_contexts`；
- 切换面板读取这些有效预算；
- 前端可禁用按钮，后端必须校验。

## 15. 后端结构

### 15.1 实例领域

```text
Instance
  id
  number
  account_id
  state: starting | active | reclaiming | invalid
  channels
  in_flight
  latest
```

`current` 是当前使用账号状态的选择，放在 manager 内部状态或列表的 `current_instance_id`；它不是策略组权重。

### 15.2 API

```text
GET    /api/instances
POST   /api/instances                       { account_id, channel? }
DELETE /api/instances/{id}
POST   /api/instances/{id}/switch           { channel? }
POST   /api/instances/{id}/reassign         { account_id }
```

`GET /api/instances` 只返回：

```json
{
  "max_instances": 2,
  "latest_instance_id": "inst-1",
  "current_instance_id": "inst-1",
  "instances": [
    {
      "id": "inst-1",
      "number": 1,
      "account_id": "acc_a",
      "state": "active",
      "channels": ["pg", "build"],
      "in_flight": 0,
      "latest": true
    }
  ]
}
```

不返回 Context/Page/Slot/资格/命中/页面计数。

### 15.3 切换

`POST /api/instances/{id}/switch { channel?: "pg" | "build" }`

1. 目标 active，或按容量执行关闭旧实例再启动目标；
2. 若目标已 active：不关闭旧实例；
3. 若容量已满且目标未 active：关闭当前实例，回收后启动目标；
4. 若指定 channel 且未激活：
   - 检查渠道/全局/组预算；
   - 在目标账号现有上下文中创建页面；
   - 预算不足返回 409；
5. 调用真实账号状态切换；
6. 切换成功后才更新 `current`；
7. 不合并 cookie，不改变策略组权重。

### 15.4 启动预载

启动流程：

```text
读取 max_contexts = N
→ 选择最多 N 个可用账号
→ 每个账号创建一个实例
→ 按默认渠道初始化
→ 失败的账号记录日志并跳过
→ 启动完成后更新 latest/current
```

- 不重复账号；
- 不伪造账号；
- 不因为某个账号失败而阻塞其他账号；
- 运行中改上限不自动补启动；
- 关闭后不自动补位。

## 16. 测试与验收

### 后端

- 启动时 `max_contexts=2` 自动启动 2 个可用账号；
- 可用账号不足时启动实际数量；
- 同账号不重复启动；
- 两个账号 → 两个实例、两个独立上下文、各一个页面；
- 同账号 PG+Build → 一个实例、一个上下文、两个页面；
- 同账号已有实例再建 → 409；
- 容量满 → 409；
- 有在途关闭 → 409；
- 切换 active 目标不关闭旧实例；
- 容量满且目标未 active → 关闭旧实例后启动目标；
- 切换调用真实账号状态切换，失败时 current 不变；
- 切换渠道预算不足 → 409，不留下半页面；
- API 不包含 Context/Page/Slot/资格/命中。

### 前端

- 账号列表头部信息集中在右侧，不使用气泡；
- 实例栏有 `[最新实例 ?] [切换] [关闭]`；
- 切换面板没有逐实例关闭；
- 切换面板渠道按钮按预算正确启用/灰掉；
- 已 active 渠道显示切换，不显示启动；
- 空闲容量没有账号占位；
- `+ 新建实例` 只在切换面板；
- 新建实例选择账号和初始渠道；
- 切换后当前账号状态实际改变；
- 1440/1024/390 三档无溢出、无遮挡、无按钮不可点；
- 390 下渠道按钮可换行，不横向滚动。

## 17. 明确不做

- 不把 Context/Page/Slot 作为用户概念；
- 不在账号列表放 `[+ 新建实例]`；
- 不在切换面板放关闭按钮；
- 不做虚假的“当前实例/最新实例”路由优先级；
- 不合并 cookie；
- 不为“同账号两渠道”增加第二层实例概念；
- 不为没有账号的空闲容量造占位账号；
- 不在切换时强行要求两个实例 active；
- 验收通过前不 push。
