## 2. 逐页调整结论

### P1 控制面板
1. **布局重排为"左右两行制"**（用户方案）：
   - 左列**纵向跨两行**＝「当前激活账号」**多行列表**（多实例/多环境时逐行列出全部活跃宿主；单实例=一行）；
   - 右区上排＝`可用账号 x/y` ＋ `实例数（当前/计划）`（"计划"=槽位表行数；实况明细=点击展开 `/surface/instances` 数据，**"实时实例"视图归此处，不再放 P3**）；
   - 右区下排＝`总请求数`，**429 计数并入其下作子指标**。
2. 错误/429 数字加 tooltip（分类：策略拒绝/冷启动/上游错误）。
3. **P1-O2 快速调用示例**：顶部加**格式选项卡**（Gemini / OpenAI / Claude，随兼容接入启用），每个格式给对应示例。

### P2 账号管理
1. **P2-O3 "Cookie 凭据组"语义确认不变**：一个凭据文件=一个浏览器会话，可含多个 Google 账号（u/0、u/1…），故呈现"凭据组 → 子账号"结构；组级操作（导入时间/会话指纹/删除整组）保留。
2. **P2-O1 账号行分模式渲染**（模式触发规则见 §3.7）：
   - 单模式：现状行＋一行细标「挂载：pg 页 ✓ / build 页 ✓」（来自 `/surface/instances`）；
   - 多模式：行内增加 **E4 渠道矩阵展开区**（账号×渠道逐格开关）＋**槽位绑定徽章**（@槽1/@槽2）＋三态徽章（资格/挂载/命中）。
3. **P2-O2 激活按钮语义**：单模式＝现状（设为默认活跃账号）；多模式拆为「设为默认活跃」＋「绑定到槽位 N」。

### P3 系统与模型配置
1. **不新增页面**；改**页面内逻辑分区 + 深度开关**（对齐 Model Profiles 既有折叠模式）：
   - 顶部新增「**显示深度功能**」总开关（默认关）：关闭=仅基础卡（基础设置/运行与调度/基础功能开关，界面保持简洁）；
   - 开启=展示深度折叠区：**渠道注册表、策略组、槽位表、路由安全、分组编排**（原 E1/E2/E3/E5 全部落位此区）。
2. **"实时实例"块从 P3-O3 移出**（迁至 P1 实例数列，见 §2-P1）。
3. P3 结构重组目标：基础区一眼干净、深度区按需展开。
4. 既有文案修正随实施走（如 P3-O1「Build 直连总开关」描述与新路由语义对齐）。

### P5 日志（新增页面）
1. `GET /logs/stream`（SSE）：级别过滤（debug/info/warn/error）、暂停/继续/清屏/下载 `.log`；后端从 logging 队列广播（不做文件 tail）。
2. 高亮：surface 决策、账号切换、4xx/5xx、borrow、熔断。
3. 与 P1 联动：点击"错误/429"数字跳转并自动过滤。
4. 分期：先只读流+过滤，后加高亮与联动。

## 3. 业务侧已成文裁定（UI 引用条款，非讨论）

1. **策略组可选**，默认不启用；单实例行为=现状（档位默认裁决）。
2. **混合组默认=有界重试的 fallback**：`每请求 max_switches=2`；熔断=滚动 10 分钟 ≥5 次失败切换→全局冷却 5 分钟；等待期每 ≤5s 发 SSE 注释帧 `: resolving-instance`；错误码：`403 surface_no_capable_account`（池内无 pro，确定性）/ `503 surface_switch_exhausted`（预算耗尽，瞬时）/ `surface_model_guard` 保留。
3. **pro/paid 模型标注**（模型列表渲染）＋**能力路由**：当前实例账号不具备 pro→切实例；全部候选无 pro→自动显式报错。
4. **borrow**：主槽不可用（切换中/冷却/未就绪）且借入槽就绪且渠道能力兼容时临时复用借入槽；仅首字节前；计入预算；不触发账号切换；**消耗借入槽账号额度→默认关，黄金场景模板一键开启**；日志 `mode=borrow from=slotN reason=...`。
5. **三渠道后无"默认渠道"**；裸模型名语义=按策略决定（矩阵见 §5.2）；模型列表多模式**全前缀+pro/paid 能力徽章**，单模式裸名+徽章。
6. **覆写三层粒度**（已确认）：规则组=模板（自动匹配）；备注标签=批量与视图；**账号级=唯一存储**（无隐藏优先级）。
7. **模式触发规则**：多模式 ⇔（渠道注册表 enabled 数 ≥2）**或**（目标槽位 N≥2）；否则单模式。
8. **防封禁有界设置**：切换预算+熔断参数落 P3 深度区「路由安全卡」。

## 4. 黄金场景（验收基准）与可行性分级

- **基准**：pro 通路（pg，承载 argon）＋ build 通路（承载 3.8f 免费模型）同时可用；免费模型在切换期间可借用对面实例。
- **级别 A（当前单浏览器可达成）**：同账号双槽（同账号 pg 页+build 页）；"借用"=同账号跨槽 ≈0 成本。
- **级别 B（黄金场景完整版）**：跨账号并存——**E4 实验已证明可行**（SAPISID 逐字节隔离、双 WS 齐连；成本 +180MB/环境），产品化（多 Realm 池并入槽位/策略组/内存预算）为后续集成工作（§5.6），无未知技术风险。
- 成本参照：页面 +66–71MB（SPIKE §14）；新环境 +180MB（PRE-P1 §E4）；实例数旋钮旁分级成本示警。

## 5. 核心逻辑定稿（2026-10-18 补；反矛盾基线）

> 本节把「用户侧怎么用、多实例间策略组怎么默认分配」一次定死；与其余章节冲突时，以本节为准。

### 5.1 唯一决策管线（一处一责定律）

任何请求只走一条管线；任何 UI/配置元件只能编辑管线上的**一个**环节：

**①能力解析**（模型→chat-only / free-capable）→ **②候选池**（默认推导或显式钉死）→ **③组约束**（可选：收窄账号集/渠道/实例预算/权重）→ **④排序**（黏性所有权→冷却健康→轮转/权重）→ **⑤实例落地**（热实例直用→预算内惰性建页→顺延候选）→ **⑥失败链**（首字节前统一顺延：借入（若开）→换实例（计预算 ≤2/请求）→耗尽显式报错）。

**三句硬定律**：
1. **能力不可配置、只可收窄**——模型↔渠道/账号资格由系统推导；组与覆写只能缩小候选集与加权，不能改写资格；
2. **渠道在①定死、链内不换面**——失败顺延只换账号（同渠道同能力），绝不静默跨面（build↔pg）；
3. **换号只在请求边界**——在途流永不打断；改道计预算、可 grep、对客户端可见；不降级、不换模型。

**元件挂号（一处一责；两处管同一件事＝bug）**：

| 元件 | 归属环节 |
|---|---|
| 模型列表 pro/paid 徽章 | ①（只读视图） |
| 策略组 / 槽位表 / 渠道矩阵 | ③ |
| 模型覆盖/钉死（账号级唯一存储） | ②（显式入口） |
| 调度权重 | ④ |
| 实例配额 / 内存预算 / 实时实例 | ⑤ |
| 路由安全卡（预算/熔断） | ⑥ |
| Model Profiles（流式/超时/安全） | 落地参数，不参与路由 |

### 5.2 裸名决策矩阵（R3.4 定稿并入）

| 场景 | 裸名解析 |
|---|---|
| 单渠道启用 | 直接用该渠道（=今天行为） |
| 多渠道、无策略组 | ①用**当前已挂载实例**（决策日志注「资源事实推导」）→②缺省候选链（free-capable 双面许可优先 build；chat-only 强制 pg）→③显式 4xx |
| 有策略组 | 按编排链（候选池→排序→顺延）选择 |
| 前缀名（多模式） | 定向渠道：未挂载→有界等待（就绪或超时显式报错）；渠道被禁→403；与能力冲突→4xx |
| 第三渠道启用后 | 无隐式「默认渠道」（系统不得硬编码偏好）；一律走上述推导 |

### 5.3 用户侧使用逻辑（零配置即完整）

1. 导入 cookies → 自动探 tier/email → **即用**；不建任何组/槽位即可使用（范围=账号池能力）。
2. 黏性=当前实例所有权；新请求优先复用；429→（账号×渠道×模型）冷却并顺延（≤2 次/请求）；熔断=滚动 10 分钟 ≥5 次失败切换→全局冷却 5 分钟；等待期每 ≤5s 发 SSE `: resolving-instance`。
3. 单模式=现状界面；多模式才出现前缀/矩阵/槽位 UI（触发规则见 §3.7）。
4. 不降级、不换模型、不静默改道；全部改道可 grep（§5.1 定律 3）。

### 5.4 多实例 × 策略组：默认分配逻辑（零配置行为）

1. **组＝约束层，不是第二套路由**：组只做四件事——账号集（tier/email 匹配）、allowed_surfaces、max_page_instances、排序权重。
2. **零配置默认＝隐式全局组**：全部账号；渠道许可=各账号现状；实例预算初值 2（对齐现役，可调）；权重相等；备用预热关；borrow 关。
3. **成员解析**：组**有序、首个命中生效**（P3 展示组序＋每账号「命中组」徽章）；空组/停用组视同不存在；未命中→按 tier 落自动组（free→build、pro→chat，可改）。
4. **实例分配序**：按 §5.1-④ 排序逐个候选落地；任一候选不可用（预算满/冷却/未就绪/上游失败）→顺延（计预算）；全链不可用→按原因显式报错（403/429/503 细分；混合组无 pro 号→`surface_no_capable_account`，报错携带命中组名）。不排队、不静默跨面。
5. **槽位**＝预留实例位（账号×渠道配置行）；同一账号可占多行（pg+build＝级别 A）；「实例数（当前/计划）」的「计划」来源＝槽位行。
6. **黄金模板（一键）**：pro@pg 槽＋free@build 槽＋borrow 开＋备用预热开→级别 A 全功能；跨账号并存（级别 B）＝槽位行落到 Realm（§5.6）。
7. **实例预算＝三层计数器（均在 §5.1-⑤ 判定，取最严）**：全局硬顶（总开的实例数；零配置时=隐式全局组预算，初值 2，防多组叠加超内存）＋ 渠道预算（pg / build / 官网 各自同时开启的实例数上限）＋ 组预算（max_page_instances）；级别 B 再叠环境数预算（§5.6）。任一不足＝该候选「不可用」→ 统一顺延（§5.1-⑥）；落位：P3 深度区（渠道注册表旁），P1 只读展示（当前/计划）。

### 5.5 主动维护（不参与请求决策）

- 空闲回收 900/1800s（现状）；备用预热（选开，+~70MB/页→切号近瞬时；默认关，黄金模板开）。
- `auto_switch`（若接线）：**只影响新会话默认排序**——仅在无在途流时再平衡，绝不重建/触碰在役实例。
- 熔断/预算/切换事件全程可 grep；P1 数字↔P5 日志联动过滤。

### 5.6 Realm 池挂点（级别 B）

只扩展 §5.1-⑤ 容器层：槽位行→Realm（独立 cookie jar，+180MB/环境）；③-④ 语义原样复用；预算＝「实例数＋环境数」双预算；接入点＝session/context 管理层（`session.py`）＋编排器。开放参数仅剩其二（§7-5）。
