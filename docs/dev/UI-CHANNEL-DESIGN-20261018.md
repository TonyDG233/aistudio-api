## 2. 逐页调整结论

### P1 控制面板
1. **布局重排为"左右两行制"**（用户方案）：
   - 左列**纵向跨两行**＝「当前激活账号」**多行列表**（多实例/多环境时逐行列出全部活跃宿主；单实例=一行）；
   - 右区上排＝`可用账号 x/y` ＋ `实例数（当前/计划）`（"计划"=槽位表行数；实况明细=点击展开 `/surface/instances` 数据，**"实时实例"视图归此处，不再放 P3**）；
   - 右区下排＝`总请求数`，**429 计数并入其下作子指标**。
2. 错误/429 数字加 tooltip（分类：策略拒绝/冷启动/上游错误）。
3. **实例数卡微调（2026-10-20 定）**：
   - 卡面只保留大数字 `当前 / 计划`；下方用与「成功 98」一致的灰色小字（`text-xs text-gray-400`）列**计划值 > 0** 的渠道，格式 `chat 实际/计划 · build 实际/计划`；
   - 计划为 0 的渠道不显示；全部为 0 时显示 `—` 或“无计划”，不显示 `0/0`；
   - 渠道多时最多显示 2 个，其余折叠为 `+N`，hover/点击出 tooltip 或小浮层列全部；
   - 超预算只让对应比值变琥珀色，不加整句警告；
   - 卡右下提供很小的“详情”或 chevron，展开 `/surface/instances`；不整卡可点，避免误触。
4. **P1-O2 快速调用示例**：顶部加**格式选项卡**，顺序：`Gemini 原生 / OpenAI Chat / OpenAI Responses / Claude Messages / Token 计数`。
   - OpenAI Chat 与 OpenAI Responses 必须分开；Token 计数 tab 只放 `count_tokens` / `input_tokens` / `countTokens`；
   - 每个 tab 给：完整 endpoint path、Base URL、鉴权头、curl + SDK 示例、复制按钮、适用客户端（Kilo Code / Codex CLI / Claude Code / SillyTavern / LiteLLM）；
   - **地址必须用 `window.location.origin` 动态生成**，不写死 localhost；这样用户从 LAN IP 或反向代理域名打开控制台时，复制到酒馆的就是当前实际地址；
   - 酒馆填法单独给一行灰色说明 + 可复制值：
     - OpenAI Chat：Base URL `http://<origin>/v1`，完整端点 `/v1/chat/completions`
     - OpenAI Responses：Base URL `http://<origin>/v1`，完整端点 `/v1/responses`
     - Claude：Proxy/Base URL `http://<origin>`，完整端点 `/v1/messages`
     - Gemini：Base URL `http://<origin>`，完整端点 `/v1beta/models/{model}:generateContent`
   - 未启用的格式 tab 隐藏或置灰；不得展示不存在的端点；API key 只用占位符；
   - 代码块高度按内容自适应，禁止桌面端出现大块空白；移动端代码块横向滚动，tab 独立横向滚动。
5. **现有页面的硬约束（设计稿必须处理）**：
   - 移动端模型统计表不得把表头/模型名拆成竖排多行；改为横向滚动或卡片化；
   - 模型名统一去掉 `models/` 前缀，避免统计表出现同名两行；
   - 激活账号长邮箱需要明确截断/换行/tooltip 规则。
6. **Token 明细不在 P1 展开**：P1 只保留摘要或“查看统计”入口；token 用量明细归 WP6 独立统计页（见 `WP6-STATS-PAGE-DESIGN-BRIEF-20261020.md`）。

## 3. 业务侧已成文裁定（UI 引用条款，非讨论）

1. **策略组可选**，默认不启用；单实例行为=现状（档位默认裁决）。
2. **混合组默认=有界重试的 fallback**：`每请求 max_switches=2`；熔断=滚动 10 分钟 ≥5 次失败切换→全局冷却 5 分钟；等待期每 ≤5s 发 SSE 注释帧 `: resolving-instance`；错误码：`403 surface_no_capable_account`（池内无 pro，确定性）/ `503 surface_switch_exhausted`（预算耗尽，瞬时）/ `surface_model_guard` 保留。
3. **pro/paid 模型标注**（模型列表渲染）＋**能力路由**：pro-only 模型必须落到 pro/paid 账号；当前实例账号不具备 pro→在派发上游前切换/装载 pro 实例；全部候选无 pro→显式报错。当前实现只做了 chat-only 面守卫，未做账号 tier 校验，v3 必须补齐。
4. **borrow**：主槽不可用（切换中/冷却/未就绪）且借入槽就绪、渠道与额度池兼容时临时复用借入槽；仅首字节前；计入预算；不触发账号切换；**消耗借入槽账号额度→默认关，黄金场景模板一键开启**；日志 `mode=borrow from=slotN reason=...`。
5. **三渠道后无"默认渠道"**；裸模型名语义=按策略决定（矩阵见 §5.2）；模型列表规则：
   - 单模式只返回裸模型 ID；
   - 多模式只返回**启用且已实现**渠道的规范前缀（`pg/`、`build/`）；
   - `chat/`、`playground/` 仅作为输入别名，不在列表中出现；
   - `official/` 在 WP9 实现前不出现；
   - 同一模型最多按“真实渠道数”出现（可用两条规范前缀，或在一条裸条目上附 `channels` 元数据），不得按别名重复完整列表。
6. **覆写三层粒度**（已确认）：规则组=模板（自动匹配）；备注标签=批量与视图；**账号级=唯一存储**（无隐藏优先级）。
7. **模式触发规则**：多模式 ⇔（渠道注册表 enabled 数 ≥2）**或**（目标槽位 N≥2）；否则单模式。
8. **防封禁有界设置**：切换预算+熔断参数落 P3 深度区「路由安全卡」。
9. **术语边界（v3）**：策略组只是统一请求路由管线中的**约束层**（③）；渠道注册表负责启用/实现/额度池（①）；“请求路由”和“实例切换/再平衡”是两条共用资格图的流程。请求期若当前实例账号能力不足，必须保留请求、在派发上游前切换/装载合格实例，不得先发给不支持实例再报错。

## 4. 黄金场景（验收基准）与可行性分级

- **基准**：pro 通路（pg，承载 argon）＋ build 通路（承载 3.8f 免费模型）同时可用；免费模型在切换期间可借用对面实例。
- **组级渠道方向**：free 组默认只允许 build；pro 组默认 chat，可按配置允许 `[chat, build]`。这不是两套实例池，而是同一实例池上的资格约束；pro 进 build 属于跨面回退，优先 free。
- **级别 A（当前单浏览器可达成）**：同账号双槽（同账号 pg 页+build 页）；"借用"=同账号跨槽 ≈0 成本。
- **级别 B（黄金场景完整版）**：跨账号并存——**E4 实验已证明可行**（SAPISID 逐字节隔离、双 WS 齐连；成本 +180MB/环境），产品化（统一 Context 池并入槽位/策略组/内存预算）为后续集成工作（§5.6），无未知技术风险。
- 成本参照：页面 +66–71MB（SPIKE §14）；新环境 +180MB（PRE-P1 §E4）；实例数旋钮旁分级成本示警。

## 5. 核心逻辑定稿（2026-10-18 补；反矛盾基线）

> 本节把「用户侧怎么用、多实例间策略组怎么默认分配」一次定死；与其余章节冲突时，以本节为准。

### 5.1 唯一决策管线（一处一责定律）

任何请求只走一条管线；任何 UI/配置元件只能编辑管线上的**一个**环节：

**①能力解析**（模型→chat-only / free-capable / pro-only；渠道→启用、实现、额度池）→ **②候选池**（组/账号覆盖/额度池/冷却）→ **③组约束**（可选：收窄账号集/渠道/页面预算/权重）→ **④排序**（黏性所有权→冷却健康→渠道亲和→轮转/权重）→ **⑤实例落地（派发上游前强制完成）**（复用合格槽位→切换/装载合格账号→预算内新建→挂起等待/显式报错）→ **⑥向上游发送实际请求** → **⑦首字节前失败链**（同账号重试→借入（若开）→换槽位（计预算 ≤2/请求）→熔断→耗尽显式报错）。

**三句硬定律**：
1. **能力不可配置、只可收窄**——模型↔渠道/账号/额度池资格由系统推导；组与覆写只能缩小候选集与加权，不能改写资格；
2. **渠道在①定死、链内不换面**——失败顺延只换账号/槽位（同渠道同能力），绝不静默跨面（build↔pg）；
3. **换号只在请求边界**——在途流永不打断；请求在切换/装载期间保持 pending，不先发给不支持实例；改道计预算、可 grep、对客户端可见；不降级、不换模型。

**两条流程（共用资格图，顺序不同）**：
- 请求路由：渠道→候选→排序→槽位落地→发送；
- 实例切换/再平衡：槽位紧急度→合格账号→最受限槽位优先→渠道亲和→装载；`auto_switch`/回收/补位走这条，不触碰在途流。

**元件挂号（一处一责；两处管同一件事＝bug）**：

| 元件 | 归属环节 |
|---|---|
| 模型列表 pro/paid 徽章 | ①（只读视图） |
| 渠道注册表（enabled / implemented / quota_pool / max_pages） | ① |
| 策略组 / 槽位表 / 渠道允许矩阵 | ③（约束/预留，不是独立池） |
| 模型覆盖/钉死（账号级唯一存储） | ②（显式入口） |
| 调度权重 | ④ |
| 实例配额 / 内存预算 / 实时实例 / 上下文池 | ⑤ |
| 路由安全卡（预算/熔断） | ⑥ |
| Model Profiles（流式/超时/安全） | 落地参数，不参与路由 |

### 5.2 裸名决策矩阵（R3.4 定稿并入）

| 场景 | 裸名解析 |
|---|---|
| 单渠道启用 | 直接用该渠道（=今天行为） |
| 多渠道、无策略组 | ①用**当前已挂载实例**（决策日志注「资源事实推导」）→②缺省候选链（free-capable 双面许可优先 build；chat-only 强制 pg）→③显式 4xx |
| 有策略组 | 按编排链（候选池→排序→顺延）选择 |
| 前缀名（多模式） | 定向渠道：未挂载→有界等待（就绪或超时显式报错）；渠道被禁→403；与能力冲突→4xx。输入别名 `chat/`、`playground/` 归一 `pg`；模型列表只列规范前缀 `pg/`、`build/`，`official/` 未实现前不列 |
| 第三渠道启用后 | 无隐式「默认渠道」（系统不得硬编码偏好）；一律走上述推导 |

### 5.3 用户侧使用逻辑（零配置即完整）

1. 导入 cookies → 自动探 tier/email → **即用**；不建任何组/槽位即可使用（范围=账号池能力）。
2. 黏性=当前实例所有权；新请求优先复用；429→（账号×渠道×模型）冷却并顺延（≤2 次/请求）；熔断=滚动 10 分钟 ≥5 次失败切换→全局冷却 5 分钟；等待期每 ≤5s 发 SSE `: resolving-instance`。
3. 单模式=现状界面；多模式才出现前缀/矩阵/槽位 UI（触发规则见 §3.7）。
4. 不降级、不换模型、不静默改道；全部改道可 grep（§5.1 定律 3）。

### 5.4 多实例 × 策略组：默认分配逻辑（零配置行为）

1. **组＝约束层，不是第二套路由**：组做五件事——账号集（tier/email 匹配）、allowed_surfaces、允许额度池、页面预算、排序权重。组不拥有独立实例池。
2. **零配置默认＝隐式全局组**：全部账号；渠道许可=各账号现状；权重相等；备用预热关；borrow 关。默认页面预算见 §5.4-7。
3. **成员解析**：组**有序、首个命中生效**（P3 展示组序＋每账号「命中组」徽章）；空组/停用组视同不存在；未命中→按 tier 落自动组（free→build、pro→chat，可改）。
4. **请求期分配序（派发上游前强制完成）**：按 §5.1-④ 排序候选；当前槽位账号能力不足（pro-only/tier/额度池/渠道不匹配）但槽位空闲→切换/装载合格账号；槽位在途→用其它空闲槽或新建；无可用槽→挂起请求等待（≤5s `: resolving-instance`）或按原因显式报错。**不得先把请求发给不支持实例再报错。**
5. **槽位**＝预留实例位（账号×渠道配置行）；同一账号可占多行（pg+build＝级别 A）；「实例数（当前/计划）」的「计划」来源＝槽位行。槽位是预留/优先级，不是永久 Context。
6. **黄金模板（一键）**：pro@pg 槽＋free@build 槽＋borrow 开＋备用预热开→级别 A 全功能；跨账号并存（级别 B）＝不同槽位落到独立 Context（§5.6）。pro 组可配 `allowed_surfaces: [chat, build]`；free 组默认 `[build]`，这是资格约束，不是独立池。
7. **预算＝页面数 + 环境数分开计数**：
   - 页面预算：全局 `global_max_pages`、渠道 `channels.<ch>.max_pages`、组 `max_pages`，取最严；零配置建议 `global=2, pg=1, build=1`，强制黄金模板各留一个位置；单渠道要吃满 2 页时显式调高该渠道并接受另一渠道被挤占。
   - 环境预算：`max_contexts`（含首个 Context），与页面数独立；取消 `max_realms` 与 `global_max_instances` 的重叠。
   - 任一不足＝该候选不可用→统一顺延；全链不可用按 403/429/503 细分。
8. **额度池（QuotaPool）**：账号背后的模型限额池（free/pro/…）是资格，不是模型清单。渠道声明 `quota_pool`，账号声明可用额度池；资格 = 渠道额度池 ∈ 账号额度池。运行时限额/冷却由 rotator 记录。free 默认只进 build，pro 可进 pg/build；pro 进 build 属于跨面回退，优先 free。
9. **实例切换方向（后台/补位）**：先按紧急度选槽位（失效/冷却 > 空槽补位 > 策略变更 > 空闲回收）；对每个槽位筛合格账号；**最受限槽位优先**（合格账号最少者先分配）；槽内排序 = 渠道亲和（free→build、pro→pg 原生；pro→build 回退）→ 黏性 → 占用惩罚 → 权重/请求量 → last_used → account_id。在途槽位不换绑。
10. **模型列表**：单模式只列裸 ID；多模式只列启用且已实现渠道的规范前缀（`pg/`、`build/`）；`chat/`、`playground/` 仅输入别名，不列；`official/` 未实现不列；同一模型最多按真实渠道数出现。

### 5.5 主动维护（不参与请求决策）

- 空闲回收 900/1800s（现状）；备用预热（选开，+~70MB/页→切号近瞬时；默认关，黄金模板开）。
- `auto_switch`：只处理**空闲槽位/新会话排序**，不触碰在途槽位；切换方向按 §5.4-9 的槽位渠道角色、组资格、额度池和渠道亲和计算，不再是“全局切一个默认账号”。
- 熔断/预算/切换事件全程可 grep；P1 数字↔P5 日志联动过滤。

### 5.6 统一 Context 实例池（级别 B）

只扩展 §5.1-⑤ 容器层：所有 Context 是平等实例槽，**没有默认会话/Realm 分立**；槽位行是预留/优先级，不是永久账号绑定；空闲 Context 可以卸载旧账号、装载目标账号（Ark `ContextPool` 语义：`maxContexts`、按 rotation 再平衡、fast switch）。预算＝「页面数＋Context 数」双预算，页面与 Context 分开计数；接入点＝session/context 管理层＋编排器。开放参数：`max_contexts` 默认 2、渠道 `max_pages` 默认 1/1。
